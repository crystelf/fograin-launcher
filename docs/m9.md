# M9：整合包、数据包、诊断与下载分类

> 状态：完成 · 2026-11-17（服务器功能于同日移除）
> 范围：崩溃分析与诊断包导出、按世界管理的数据包、整合包导入/导出与在线浏览、
> 下载页的整合包 / 数据包 / 资源包分类、桌面拖放导入；CLI、FFI 与 Compose UI 接线。
> 明确不做：服务器列表与 Ping（已从产品范围移除）、整合包增量更新、微软正版登录（M11）、
> 内容图标网络缓存、自动更新、Android 游戏运行时（M12）。

## 1. 范围与取舍

| 能力 | M9 | 说明 |
| --- | --- | --- |
| 崩溃分析 | ✅ | `crash-reports/*.txt`、`logs/latest.log`、`hs_err_pid*.log`、最近 stdout |
| 诊断包 | ✅ | 脱敏 zip：分析报告、日志、崩溃报告、实例/Java 摘要 |
| 数据包本地管理 | ✅ | 按世界 `saves/<world>/datapacks`，启用/禁用、删除、本地 `.zip` 导入 |
| 数据包在线安装 | ✅ | 下载页「数据包」分类；选择实例 + 世界后安装 |
| 整合包导入 | ✅ | Modrinth `.mrpack`、CurseForge `.zip`、HMCL `.zip`、MultiMC/Prism 目录 |
| 整合包导出 | ✅ | `.mrpack`（`modrinth.index.json` + `overrides/`），输出到 `<data root>/exports` |
| 整合包在线浏览 | ✅ | 下载页「整合包」分类接 Modrinth / CurseForge；安装时下载归档并自动导入 |
| 拖放导入 | ✅ | 桌面窗口接收 `.mrpack` / `.zip` / MultiMC 目录，拖动时显示全窗提示 |
| 下载分类 | ✅ | 资源包 / 光影 / 模组沿用内容浏览器；无实例时允许浏览 |
| 服务器 | ❌ 已移除 | 列表、Ping、SRV、局域网、`servers.dat` 与快速加入在 2026-11-17 全部删除 |
| 整合包增量更新 | ❌ 后续 | 导入时记录来源与文件清单，更新流程留给 M9.1 |
| 内容图标/封面 | ❌ 后续 | 继续使用字母色块，网络图片加载仍缺 `commonMain` 解码 |

取舍理由：

1. **下载分类统一复用内容浏览器。** 整合包与数据包都变成 `ContentKind`（`modpack` / `datapack`），
   搜索和版本列表复用同一套 Modrinth / CurseForge 代码；整合包安装到「新实例」，数据包安装到
   「实例 + 世界」，与模组/资源包的「安装到实例」在同一个页面语言里表达。
2. **整合包浏览 = 下载归档 + 现有导入。** `modpack.install` 先排队下载 `.mrpack`，完成后调用本地
   导入流程，因此浏览页不需要第二套安装器；增量更新仍留到 M9.1。
3. **数据包按世界。**

   数据包写进 `saves/<world>/datapacks`，`ContentPlan` 因此增加 world 目标目录；安装完成后不写实例
   内容索引，仍由 `datapacks.list` 扫描。
4. **拖放与主页菜单复用同一入口。** 桌面 AWT `DropTarget` 和主页三点菜单都调用
   `modpack.importPath`，确认 sheet 与文件选择器完全一致。
5. **诊断只做规则引擎**，不内嵌模组数据库。规则可扩展（内嵌默认表 + 用户覆盖目录），首批覆盖
   Java、内存、显卡、文件损坏、模组依赖/重复、Mixin、OptiFine、加载器重复与 tick 崩溃。
6. **服务器整体移除。** 列表、Ping、SRV、局域网与快速加入不再属于产品范围；相关代码、
   `launch.start` 的 `server` 参数与第五个导航目的地全部删除。

## 3. 服务器（已移除）

2026-11-17 的产品决定把服务器相关能力整体移除：`servers.json` / `servers.dat` 同步、Server List
Ping、SRV、局域网组播、快速加入与第五个「服务器」目的地都不再存在。`launch.start` 不再接受
`server`，启动参数回到普通主菜单；`fg-world` 只保留世界、数据包与 `level.dat` 解析。
如果后续重新引入，应作为独立里程碑重新设计，而不是恢复旧代码。

## 4. 崩溃分析

### 4.1 来源

| 来源 | 路径 | 优先级 |
| --- | --- | --- |
| 本次启动 stdout | 事件队列 `game.line` 环形缓冲，最后 2000 行 | 1 |
| 最新日志 | `<game dir>/logs/latest.log` | 2 |
| 崩溃报告 | `<game dir>/crash-reports/*.txt`，按修改时间 | 3 |
| JVM 崩溃 | `<game dir>/hs_err_pid*.log` | 4 |

### 4.2 规则

内嵌 `rules/default.toml`，用户可在 `<data root>/diag/rules/*.toml` 增补或覆盖同 id 规则。

```toml
[[rule]]
id = "java.version"
severity = "error"           # error | warning | info
source = "any"               # log | crash | hsErr | any
pattern = 'UnsupportedClassVersionError|class file version \d+\.\d+'
title = "Java 版本不匹配"     # 展示文案随规则保存，M10 i18n 时迁入 composeResources
body = "游戏或模组需要更高版本的 Java。"
fix = "installJava"           # none | installJava | openJavaSettings | openContent | disableMod | openGraphics | openLogs
```

首批规则：`java.version`、`java.memory`、`graphics.driver`、`graphics.opengl`、
`file.corrupt`、`mod.dependency`、`mod.duplicate`、`mod.conflict`、`mixin.failure`、
`optifine.conflict`、`loader.duplicate`、`tick.crash`。

### 4.3 输出

```json
{"findings":[{"id":"mod.dependency","severity":"error","confidence":0.9,
  "title":"缺少模组前置","body":"…","excerpt":"…","line":1234,
  "fix":"open_content","fixLabel":"查看模组"}],
 "summary":"…","logLines":2000,"crashReports":1,"analyzedAtMs":0}
```

置信度：命中崩溃报告的规则 0.9，命中 `latest.log` 的 0.75，命中 stdout 的 0.6；
同一规则只保留最高置信度的一条，按 severity → confidence 排序，最多 20 条。

### 4.4 诊断包

`<data root>/diagnostics/<instance>-<yyyyMMdd-HHmmss>.zip`：

- `report.md`：分析结论、实例摘要、Java、内存、加载器、规则命中片段。
- `logs/latest.log`（最后 2000 行，与分析的尾部窗口一致）。
- `crash-reports/<latest>.txt`。
- `instance.json`：实例设置与内容索引（**不含账户与令牌**）。
- `manifest.json`：生成时间、平台、启动器版本、来源列表。

## 5. 数据包

- 位置：`<game dir>/saves/<world>/datapacks/`；文件 `.zip`，目录也接受。
- 启用/禁用：`.disabled` 后缀，与模组一致。
- 元数据：`pack.mcmeta` 的 `pack_format` 与 `description`，复用 `fg-content` 的读取逻辑。
- 导入：复制本地文件/目录到目标世界；重名时追加 `-2`。
- 世界必须存在且是安全名称；未选择世界时 UI 提示先选世界。

## 6. 整合包

### 6.1 识别

| 输入 | 识别方式 | 结果 |
| --- | --- | --- |
| `.mrpack` | zip 内 `modrinth.index.json` | 名称、版本、MC、加载器、文件数 |
| CurseForge `.zip` | zip 内 `manifest.json` + `manifestType=minecraftModpack` | 名称、版本、MC、加载器、文件数 |
| HMCL `.zip` | zip 内 `modpack.json` + `.minecraft/` | 名称、版本、MC、加载器 |
| MultiMC/Prism 目录 | `mmc-pack.json` + `minecraft/` | 名称、MC、加载器；作为外部目录导入 |
| 纯 `.minecraft` 目录 | 现有 `instances.import` | 不重复实现 |

### 6.2 导入流程

1. `modpack.inspect` 读取清单，返回可编辑的实例名称、MC、加载器、文件数与覆盖目录数。
2. `modpack.import`：
   - 创建实例（id 去重），写入 MC 与加载器。
   - 若实例未安装，先排队基础安装（原版 + 加载器），等待完成。
   - 再排队整合包任务：逐文件下载（SHA-1/SHA-512 校验）→ 解压 `overrides/` → 写
     `instances/<id>/modpack.json` 与内容索引。
3. UI 会看到连续任务：`整合包下载:<名称>`（在线安装时）→ `install:<版本>` → `整合包:<名称>`。

### 6.3 在线安装

`modpack.install` 解析项目版本 → 排队一个 `modpack.download` 任务把 `.mrpack` / CurseForge zip 下载到
`cache/modpacks/` → 下载成功后调用与本地文件完全相同的导入流程。失败时下载任务标记失败，不会创建实例。

### 6.4 导出

`modpack.export` 生成 `.mrpack`：

- `modrinth.index.json`：实例 MC、加载器版本、内容索引中的文件（保留来源、项目、版本、SHA-1）。
- `overrides/`：`config/`、`defaultconfigs/`、`options.txt`、`resourcepacks/`、`shaderpacks/`、
  `saves/` 之外的本地文件（单文件上限 32 MiB，总量上限 256 MiB）。
- 输出到 `<data root>/exports/<name>-<timestamp>.mrpack`，返回路径与大小。

## 7. FFI 契约

| 方法 | 参数 | 返回 |
| --- | --- | --- |
| `diag.logs` | `instanceId` | `{sources:[{kind,name,path,exists,modifiedMs,sizeBytes,lines}],crash?,texts:{stdout?,log?,crash?,hsErr?},rules}` |
| `diag.analyze` | `instanceId` | `{findings,summary,analyzedAtMs}` |
| `diag.export` | `instanceId` | `{bundle:{path,sizeBytes,files},analysis}` |
| `datapacks.list` | `instanceId,world` | `{items,count}` |
| `datapacks.toggle` | `instanceId,world,fileName,enabled` | `{items}` |
| `datapacks.delete` | `instanceId,world,fileName` | `{items}` |
| `datapacks.import` | `instanceId,world,path` | `{items,fileName}` |
| `modpack.inspect` | `path` | `{kind,name,version,minecraft,loaderKind,loaderVersion,summary?,author?,files,overrides?,sourcePath,gameDir?,external,skipped}` |
| `modpack.import` | `path,name?` | `{instanceId,taskId,pack,external}` |
| `modpack.export` | `instanceId` | `{path,sizeBytes,files}` |
| `content.search` | `source?,kind,query,instanceId?,loader?,…` | `{projects,total}`；`kind` 新增 `modpack`、`datapack` |
| `content.install` | `source?,projectId,versionId?,instanceId,kind,world?,installDependencies?` | 数据包必须带 `world`；`installDependencies=false` 只装本体 |
| `modpack.install` | `source?,projectId,versionId,name?` | `{taskId,name,versionId,versionNumber,source}`；下载归档后自动导入 |
| `tasks.list` | — | `{id,name,state,fraction,speed}` 列表；`state` 含 `running/paused/succeeded/failed/cancelled` |
| `tasks.pause` / `tasks.cancel` | `taskId` | 暂停保留已下载部分；停止结束任务并保留历史行 |
| `tasks.resume` | `taskId` | 重放原 RPC 并返回新的 `taskId`；下载缓存直接命中，不重复传输 |

所有事件继续走 `task.*`；诊断分析与数据包扫描是短 RPC，整合包归档下载与内容安装进入任务队列。
暂停通过 `Control::pause` 停止当前图；由于图节点是 `FnOnce`，继续操作会重放原始 RPC（`install.start`、
`content.install`、`modpack.install/import`、`java.install`），由下载缓存避免重复字节。

## 8. UI

### 8.1 导航

导航保持四个目的地：主页 / 实例 / 下载 / 设置。M9 不新增顶级页面；服务器目的地在同日移除。
下载队列是导航壳内的独立页面（保留底部导航/侧栏，返回原页面），不是第五个目的地；页头与返回按钮和实例详情页对齐。

### 8.2 下载分类

- 「整合包」分类：项目网格 + 版本选择 sheet；目标显示为「新实例」，主按钮「创建实例并导入」。
  安装先下载 `.mrpack`（任务队列显示进度），完成后自动创建实例、安装基础游戏/加载器并解压内容。
- 「数据包」分类：目标实例 chip + 世界下拉；安装写入选中的 `saves/<world>/datapacks`。
- 「资源包 / 光影 / 模组」：无实例时仍可浏览，页面顶部给出一条提示，安装按钮在选中实例前禁用。
- 每个分类的搜索框占位符与主按钮文案随分类变化，避免「搜索模组、资源包或光影」这种混合提示。

### 8.3 拖放导入与主页入口

- 主页右上角三点菜单新增「导入整合包…」，调用与文件选择器相同的确认 sheet。
- 桌面窗口安装 AWT `DropTarget`：拖动 `.mrpack`、`.zip` 或 MultiMC/Prism 实例目录时全窗显示
  「松开以导入整合包」遮罩，松手后进入确认 sheet；其它文件给出提示而不是静默失败。
- 拖放与菜单都调用 `modpack.importPath`，不复制第二套解析逻辑。

### 8.4 诊断页

- 入口：实例设置 → 「日志与诊断」。
- 页头：返回、标题、刷新、导出诊断包（图标按钮）。
- 结论区：最多 3 条 finding 卡片（severity 色），显示标题、说明、命中行号与修复按钮；
  更多建议显示「另有 N 条建议已写入诊断包」。
- 日志区：`SegmentedTabRail`（最新日志 / 崩溃报告 / 本次输出 / JVM 崩溃），等宽字体、行号、
  自动滚到底部；ERROR / Exception 行使用 error 色，WARN 使用 tertiary 色。
- 无崩溃时显示「没有发现已知问题」的轻量卡片，并保留日志入口。

### 8.5 数据包分页

- 实例详情的分类轨新增「数据包」，顶部世界选择器；无世界时直接空状态并提示先创建世界。
- 列表行与模组一致：标题、格式/大小、启用开关、删除；导入按钮打开文件选择器。
- 实例详情打开时预加载第一个世界的数据包，分类轨计数不会停留在 0。

### 8.6 实例详情页头

实例详情只保留页面顶部的一行身份：实例名 + 搜索 + 开始游戏 + 收藏 + 三点菜单。原来的第二行
（实例图标 / 版本 / 开始游戏 / 设置 / 收藏）已删除；实例设置、复制目录、删除都收进三点菜单。
窄窗口下开始游戏收缩为 40 dp 图标按钮，保证实例名完整显示。

### 8.7 下载队列页

- 入口：主页三点菜单「下载队列」、主页任务卡「查看队列」、下载页「正在下载」卡片；下载页三点菜单也保留入口。
- 独立页面：共享页头与导航侧栏/底栏，返回按钮与实例详情页位置一致；展示进行中与已暂停任务，
  附最近完成/失败/停止历史。
- 扁平列表：无汇总卡片和边框，顶部一行「进行中/已暂停」摘要与总速度；任务行只用标题、状态、
  进度条和行间分隔线。每条任务显示标题、进度百分比、实时速度、进度条；操作有暂停、继续、停止。
- 主页任务卡内联同一组暂停/继续/停止按钮，不打开整页也能控制；总速度与任务数在卡头显示。
- 暂停调用 `tasks.pause`，继续调用 `tasks.resume` 重放原 RPC，停止调用 `tasks.cancel`；队列每 250 ms
  随 `task.progress` 刷新，操作后立即重新拉取 `tasks.list`。

### 8.8 实现记录与取舍

- **规则文案**内嵌在 `rules/default.toml`（`title` / `body`），`id` 是稳定键；M10 的 i18n 会把文案迁入
  `composeResources`，不再走 `title_key` 二次查表。
- **整合包导入**复用 `install.start` 完成基础游戏与加载器，成功后排队第二个「整合包:<名称>」图；
  两个阶段共用任务队列。外部 MultiMC/Prism 目录只注册不复制。
- **整合包浏览**复用 `content.search` / `content.versions` 的 `modpack` kind；安装由
  `modpack.install` 下载归档后调用本地导入，和拖放/文件选择器走同一个入口。
- **数据包**复用内容安装计划，但 `ContentPlan` 增加 world 目标目录；数据包不写实例内容索引，
  仍由 `datapacks.list` 扫描。
- **导出**把本地内容全部写进 `overrides/`，不写 `files[]`：内容索引没有原始下载 URL，
  保证导出的包一定能被重新导入；代价是体积更大。
- **诊断包**只读本地数据，`instance.json` 不含账户、令牌与密码；规则覆盖目录为 `<data root>/diag/rules/`。
- **异常退出**时先跑一次 `diag.analyze`，告警文案直接给出首条 finding 的标题与建议，并把结果预填进
  诊断页。
- **CurseForge 整合包**的文件统一落到 `mods/`：manifest 不带分类，按项目 `classId` 区分资源包/光影需要
  额外请求；大多数整合包把它们放在 `overrides/`，因此不影响常见场景（已列入 backlog）。

## 10. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 整合包来源文件不可变 | 中 | 导入后写 `modpack.json` 记录来源，更新流程延后 |
| 整合包浏览依赖 Modrinth / MCIM | 中 | 搜索失败时显示重试，不阻塞本地导入与拖放 |
| 下载后导入分两阶段 | 中 | 下载成功但基础安装失败会留下空实例；增量更新里程碑补回滚 |
| 拖放仅桌面可用 | 低 | Android 继续走文件选择器；共享遮罩只在桌面触发 |
| 大整合包下载时间长 | 中 | 复用 fg-task 并发与断点续传；UI 显示任务队列进度 |
| 诊断规则误报 | 中 | 置信度排序 + 只做建议，不自动修改文件 |
