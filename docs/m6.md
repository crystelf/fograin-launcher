# M6：Java 运行时自动下载与管理

> 状态：完成 · 2026-11-15  
> 范围：Mojang 官方 JRE 目录、`runtimes/` 安装与删除、安装/启动自动补全、CLI 与 Compose 管理页。

## 1. 交付内容

| 能力 | 实现 |
| --- | --- |
| 运行时目录 | `runtimes/<vendor>-<component>-<version>-<arch>/` |
| 来源 | Mojang `all.json` 官方运行时目录（与官方启动器一致） |
| 版本选择 | 版本 JSON 的 `javaVersion.component` 优先，否则按 `majorVersion` 精确匹配 |
| 旧版本兼容 | macOS arm64 / Windows arm64 自动回退 x86_64；macOS 走 Rosetta，Windows 走系统仿真 |
| 安装 | 按文件清单下载、SHA-1 校验、目录/符号链接/可执行位、写入 `fograin-runtime.json` |
| 自动补全 | `[java] auto_download = true` 时，安装加载器或启动游戏在无 Java 时先下载再继续 |
| 管理页 | 设置 → Java 运行时：已安装列表、可下载列表、下载进度、删除、自动下载开关 |
| 实例绑定 | 游戏设置的 Java 下拉框列出系统与托管运行时，可写 `[override] java` |

## 2. 分层

```text
fg-java
  catalog.rs    Mojang all.json → JavaRuntimeCandidate（platform/arch/component）
  managed.rs    RuntimePlan / RuntimeMarker / JavaManager / 下载与删除
  runtime.rs    既有 release、PE/Mach-O/ELF 解析（复用）
  discover.rs   既有扫描器；修复 macOS jre.bundle/Contents/Home 的深度
  matching.rs   既有精确/邻近 major 选择（复用）

fg-ffi
  java.list / java.catalog / java.install / java.remove / java.policy.set
  install.start / launch.start → ensure_java()：缺 Java 时排队下载并等待

fg-cli
  java catalog / install / remove；install/launch 复用 ensure_java_for_cli()

apps/compose
  settings/JavaRuntimeScreen.kt + JavaActions + JavaUiState
```

`fg-java` 只依赖 `fg-core`、`fg-net`、`fg-task`，不接触实例模型；`fg-game` 继续只使用
`JavaRuntime`，无需知道运行时来自系统还是下载目录。

## 3. 目录与清单

Mojang 的 macOS 运行时并不以 `bin/` 为根：真正的 JDK home 是
`jre.bundle/Contents/Home/`，而 `Info.plist`、`Contents/MacOS/libjli.dylib` 和
`_CodeSignature/` 必须保留在 bundle 内。因此安装不做“扁平化”，而是把清单原样落盘：

```text
runtimes/mojang-java-runtime-delta-21.0.7-arm64/
├─ fograin-runtime.json          # 安装标记；home = jre.bundle/Contents/Home
└─ jre.bundle/
   └─ Contents/
      ├─ Home/{bin,lib,release,...}
      ├─ Info.plist
      └─ MacOS/libjli.dylib
```

`fograin-runtime.json` 记录 schema、id、vendor、component、version、major、arch、
platform、manifest SHA-1、文件数、总字节、安装时间和相对 `home`。管理页只把带标记且
`bin/java` 存在的目录当作托管运行时；扫描器对系统 JDK 与托管目录一视同仁。半成品目录会保留，
重跑同一安装即可续传。

## 4. 选择与自动补全

`RuntimeIndex::select` 的平台顺序：

- macOS x86_64：`mac-os`
- macOS arm64：`mac-os-arm64` → `mac-os`
- Windows x86_64：`windows-x64`
- Windows arm64：`windows-arm64` → `windows-x64`
- Windows x86：`windows-x86`
- Linux x86_64：`linux`
- Linux x86：`linux-i386`
- Linux arm64 / Android：无官方运行时，返回 `error.java.runtime_unsupported`

组件提示（`javaVersion.component`）优先于 major 匹配；否则选择解析出的 major 与所需
major 完全相同的最新组件。`catalog` 按 major 去重，跳过 `*-snapshot` 组件，因此管理页
只出现 Java 8 / 16 / 17 / 21 / 25（随 Mojang 目录更新）。

自动补全只在“一个运行时都找不到”时触发；已有不匹配 runtime 时沿用 M3 的降级+警告，
不会为了精确 major 悄悄下载 100 MB。触发后的流程：

1. `JavaManager::candidate()` 读取官方目录并选择组件；
2. `JavaManager::plan()` 读取组件 manifest（BMCLAPI 镜像可用）；
3. 计划写入 `cache/java/<runtime-id>.json`；
4. 以 `java:<major>` 为名排队 `TaskGraph`，进度进入 `task.progress`；
5. `launch.start` / `install.start` 等待任务结束后重新扫描并继续。

Apple Silicon 上 1.7–1.18 只有 x86_64 LWJGL natives，因此启动这些版本时
`ensure_java` 以 `X86_64` 为目标架构并要求“精确 major + 实际架构匹配”：已装 arm64
Java、或 x86_64 的 Java 17 都不算满足 Java 8 的需求，会下载 `mac-os` 的 x86_64 运行时；
关闭自动下载则返回 `error.java.x86_64_required`。

BMCLAPI 会重新序列化 JSON，manifest 的 SHA-1 与 Mojang 原始字节不同，因此只在官方
host 返回时校验 manifest 哈希；每个运行时文件仍按 SHA-1 校验。

## 5. 接口

| 方法 | 参数 | 结果 |
| --- | --- | --- |
| `java.list` | `{}` | `{runtimes, autoDownload, supported, platform, hostArch}` |
| `java.catalog` | `{}` | `{versions:[{runtimeId, major, component, version, arch, platform, fallback, installed, installedVersion?}], autoDownload, supported}` |
| `java.install` | `{major, component?}` | `{taskId, runtimeId, existing, major, component, version, files, totalBytes}` |
| `java.remove` | `{id}` | `{ok, id}`；游戏运行或同名运行时装任务进行中时拒绝 |
| `java.policy.set` | `{autoDownload}` | `{autoDownload}`，写 `launcher.toml [java]` |

`java.list` 的 runtime 行：`id`（仅托管）、`vendor`、`version`、`major`、`arch`、`home`、
`executable`、`source`、`managed`、`sizeBytes`、`installedAtMs`、`component`、`platform`。

`launcher.toml` 新增：

```toml
[java]
auto_download = true
```

旧配置没有该节时默认为 `true`。

## 6. 验收

- `cargo test --workspace`。
- `fg-cli java catalog` 在 macOS arm64 列出 Java 8/16（x86_64 兼容）与 17/21/25（arm64）。
- `fg-cli java install 21` 下载到 `runtimes/mojang-java-runtime-delta-21.0.7-arm64/`，
  `bin/java -version` 可执行，`fg-cli java list` 显示 `managed` id。
- `fg-cli java remove <id>` 删除目录；管理页删除按钮走同一接口。
- 断网时 `java install` 报 `error.java.runtime_install` / 网络错误，已下载文件保留供续传。
- `fg-cli install 1.20.1 --loader forge ...` 在没有系统 Java 时自动下载 Java 17 后继续。
- 手动真实运行时：本机 macOS arm64 安装 Java 21，`java -version` 输出
  `openjdk version "21.0.7"`（与 M6 验收一致）。
- Compose：`./apps/compose/gradlew -p apps/compose :shared:desktopTest` 与 `:desktop:test`；
  `java-page` 离屏截图已加入 `ScreensRenderTest`。

## 7. 已知限制

- 仅接入 Mojang 官方目录。Linux arm64 没有官方包，需要系统 JDK；Adoptium/Temurin
  作为第二来源列入 `docs/backlog.md`。
- 自动补全只在完全缺 Java 时触发；已有 Java 8 但启动 1.21 时仍按 M3 规则降级并警告。
- 管理页的“可下载”只列宿主架构；Apple Silicon 旧版本额外需要的 x86_64 运行时会由启动流程
  自动补全，暂不在目录里单独展示，安装后可在“已安装”列表中看到。
- 运行时下载暂不支持取消按钮（可通过任务队列取消），管理页只显示进度。
- Android 的游戏 Java 运行时属于 M12 Android 游戏运行时；当前管理页显示“不支持自动下载”。
- macOS 运行时未做公证/签名检查；M6 只下载 Mojang 原始文件，后续随安装包签名策略调整。
